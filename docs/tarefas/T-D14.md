# T-D14 — Imagem do ETL com certifi atualizado (raiz emSign ECC G3 removida)
- **Papel:** dados · **Fase:** F4 · **Issue:** #118 · **Branch:** `fix/dados-certifi`
- **Depende de:** —

## Objetivo
A imagem `ghcr.io/felipemaion/eleicoes2026-etl:latest` (coleta diária no servidor, TLS de saída com a Meta)
tem **certifi 2026.07.22**, que ainda confia na raiz **"emSign ECC Root CA - G3"** (eMudhra; intermediárias
comprometidas, removida pela Mozilla em 20/10/2026). Achado do Oracle na varredura de segurança de 25/10.

## Escopo
1. `uv lock --upgrade-package certifi` (≥ 2026.10.18, versão já limpa no outro serviço do servidor);
   conferir que nada mais mudou no lock além do necessário.
2. Teste (unidade, sem rede) que falha se o bundle do certifi contiver "emSign ECC Root CA - G3"
   (`certifi.contents()`), para a raiz não voltar num lock futuro.
3. Conferir o `Dockerfile` do ETL: a imagem usa o certifi do lock (não um pip solto nem o bundle do sistema
   com outra versão). Se usar o bundle do sistema também, documentar.
4. Handoff: como a imagem é publicada (workflow `imagem-etl` ao integrar?) e o comando para o Oracle conferir
   dentro do container (`python -c "import certifi; print(certifi.__version__)"` + grep do rótulo no cacert.pem).

## Entrega
TDD (`test:` vermelho antes do `fix:`). Handoff `docs/registro/handoffs/dados-T-D14.md`; responder `pronto T-D14`.
