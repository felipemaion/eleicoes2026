# T-B17 — ETag da API inclui a versão do build
- **Papel:** backend · **Branch:** `fix/backend-etag-versao` · **Relacionada: T-W21**

Causa da foto sumida em produção (handoff `frontend-T-W21.md`): o ETag de `apps/api/src/api/cache_http.py` depende
só de `(DT_GERACAO, URL)` com `Cache-Control: public, max-age=300`. Um deploy que muda o **formato** da resposta sem
mudar `DT_GERACAO` faz o navegador revalidar, receber 304 e seguir com o JSON antigo. A T-W21 contorna no web
(`v=<sha>` na URL); a raiz é aqui.

**Fazer:** incluir no ETag uma versão do código — o sha do build (variável de ambiente injetada na imagem pelo
`deploy.yml`/Dockerfile, ex.: `VERSAO_APP`) e, como reforço, um hash do OpenAPI calculado no startup. Sem a
variável em produção → falhar alto no startup (nada de default silencioso); em dev/testes um valor fixo explícito.
Mudanças em `deploy.yml`/Dockerfile: se forem fora do seu território, pare e peça ao orquestrador.
`/api/health` passa a expor `versao` real (hoje "0.1.0").

**Aceite:** teste de integração — mesma URL e mesmo `DT_GERACAO` com versões diferentes ⇒ ETags diferentes e sem 304;
mesma versão ⇒ 304 como antes. `make lint test`, handoff, `pronto T-B17`.
