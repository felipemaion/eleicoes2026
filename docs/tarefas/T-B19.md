# T-B19 — API lê a série de redes de `data/redes` e expõe a última coleta
- **Papel:** backend · **Branch:** `feat/backend-redes-dir-status` · **Junto com T-D09** · ADR 0008
- **Contexto:** `docs/registro/consultas/2026-10-14-oracle-redes-diario-resposta.md`. No servidor, a série de
  seguidores passa a morar em `/home/…/data/redes` (fora do alcance do rsync do Mac e dentro do backup), montada
  na API como volume ro separado de `datasets/`. A coleta grava `status.json` (formato na T-D09).

**Fazer:**
1. Diretório de redes configurável (ex.: `ELEICOES_REDES_DIR`, padrão = `<datasets>/redes` para não quebrar o
   local nem a produção atual). `infra/compose.yaml` (espelho) com o volume `../data/redes:/redes:ro` e a variável.
2. Recarregar quando a coleta promove dados novos sem precisar de restart: detectar mudança de `mtime` do
   `manifesto.json` de redes e reabrir as views (barato: checar no máximo 1×/min). ETag de `/redes*` já inclui a
   última coleta — conferir que muda.
3. `GET /api/redes` (e/ou `/api/health`) expõe a última coleta: `coletado_em`, `resultado`, `motivo`, dias desde a
   última coleta bem-sucedida (do `status.json`; ausente → nulo, sem quebrar).
4. OpenAPI regenerado; varredura cobre.

**Aceite:** integração DuckDB sobre fixtures em diretório separado; teste de recarga por mtime; status ausente,
ok e erro; `make lint test`; handoff `backend-T-B19.md`; `pronto T-B19`.
